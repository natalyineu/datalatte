Google's own documentation says it plainly: "All Maps Embed API requests are available at no charge with unlimited usage." So the cost of putting a map on your contact page is $0 and about five minutes. The real costs are quieter: a map that loads before it is needed, a frame a screen reader cannot name, a map that tells nobody your address in text, and a visitor who has to pinch and zoom to find out how to get to you.

This guide is for owners of local businesses in the US, UK, Australia and Canada who run their own site on WordPress, Squarespace, Wix or similar. It covers three ways to show your location, the attributes worth adding to the code, a privacy check that matters most in the UK, and a way to measure whether the map earns its space. If you are wondering whether you need the paid developer API, read [our Google Maps API guide](/blog/using-google-maps-api-for-local-businesses) first. This article stays on the simple end.

## First, Be Honest About What a Map Does

An embedded map is a convenience, not a ranking tool. Google's Business Profile help says: "There's no way to request or pay for a better local ranking on Google," and that local results are "mainly based on relevance, distance, and popularity." Putting a map on your site is not on that list. What it does well is remove one step for a customer who has already decided to visit.

So the order of work is: get your listing right (our [Google Business Profile checklist](/blog/google-business-profile-optimization-checklist) and the [Maps ranking factors guide](/blog/google-maps-ranking-factors-what-moves-needle-2026) cover that), then put a clean map on one page. Not ten pages. One.

## Three Ways to Show Your Location

| Method | Setup | Loads Google's map on page load? | Best for |
| --- | --- | --- | --- |
| Interactive iframe (Copy HTML from Google Maps) | Minutes, no developer | Yes (unless lazy loaded) | One location, contact page |
| Maps Embed API with a key | Needs a Google Cloud project and key | Yes (unless lazy loaded) | Directions or fixed zoom modes |
| Text address plus a "Get directions" link | Minutes | No | Pages where speed or privacy matter most |

Many small sites need only the first row. The third row is underrated, and we will come back to it.

## Method 1: Copy the Code From Google Maps

Google's Maps help describes the steps for a computer (the page gives no steps for the phone apps). To embed a map of a place: open Google Maps, go to the part of the map you want, click Menu at the top left, choose "Share or embed map", then "Embed a map", then "Copy HTML." For directions, click Directions, enter the locations, choose a route, click Share, then "Embed a map", then "Copy HTML." Google's interface changes, so if a label has moved, search for your business name first and look for Share.

Google also lists what you cannot embed: a map that includes your saved locations, a distance measurement, or an image of the map itself.

Then paste the code into a Custom HTML or embed block on your contact page. In WordPress that is the Custom HTML block; Squarespace, Wix and Shopify have equivalent embed or code blocks.

## Method 2: The Maps Embed API (When You Want Control)

The Maps Embed API gives you a URL in the form `https://www.google.com/maps/embed/v1/MAP_MODE?key=YOUR_API_KEY&PARAMETERS`. Google states "An API key is required for using the Embed API." It documents five modes:

| Mode | What it shows | Required parameter |
| --- | --- | --- |
| place | A pin for one place | `q` (name, address or Place ID) |
| view | A map at fixed coordinates | `center` |
| directions | A route | `origin`, `destination` |
| streetview | A panorama | `location` or `pano` |
| search | Results for a search | `q` |

Useful optional settings from the same page: `zoom` runs from 0 (the whole world) to 21 (individual buildings), and `maptype` is `roadmap` (the default) or `satellite`. Google also notes maps smaller than 200 px in either dimension are not supported.

If you use a key, restrict it. We cover how, and why an unrestricted key is a billing risk, in the [Maps API guide](/blog/using-google-maps-api-for-local-businesses). The embed itself is free per Google's documentation, but a key sitting in public page code can be copied by anyone, so restricting it to your site's address is sensible housekeeping.

## Add Four Attributes Before You Publish

Google's own sample iframe includes `loading="lazy"`, `allowfullscreen` and `referrerpolicy="strict-origin-when-cross-origin"`. Check that your pasted code has the first two and add the third if you want to be explicit. Then add a `title`, which Google's sample does not show.

```html
<iframe
  title="Map showing Corner Cafe, 12 High Street"
  width="100%"
  height="350"
  style="border:0"
  loading="lazy"
  allowfullscreen
  referrerpolicy="strict-origin-when-cross-origin"
  src="PASTE-YOUR-GOOGLE-EMBED-URL-HERE">
</iframe>
```

Here is why each one earns its place.

**title.** The MDN documentation says screen reader users can use the `title` attribute to label an iframe, and that without it they "have to navigate into the iframe to determine what its embedded content is." The W3C's accessibility technique H64 makes the same recommendation. Describe the content concisely, as in the example above.

**loading="lazy".** MDN defines it as deferring "loading of the iframe until it reaches a calculated distance from the visual viewport," which "improves the performance and cost in most typical use cases." Google's web.dev guidance says lazy loading for iframes is supported in the major browsers (it lists Chrome 77, Edge 79, Firefox 121 and Safari 16.4). It also says omitting the attribute behaves like `eager`, so the map loads immediately if you leave it out. MDN adds that deferral only happens when JavaScript is enabled. One practical note from me, not a source: if the map sits at the very top of the screen on a phone, lazy loading gains you nothing, so put it below your address and hours.

**referrerpolicy.** MDN says the default is `strict-origin-when-cross-origin`, which sends the full address only for same-site requests and just the site name over HTTPS to other sites. Setting it explicitly matches Google's sample and avoids surprises.

**Width and height.** Google's sample uses fixed 600 by 450. For phones, set `width="100%"` (my suggestion) with a height around 300 to 400 pixels so the map does not push your phone number off the first screen. Check on a real phone, not a desktop window.

MDN also warns that every iframe "requires increased memory and other computing resources," so one map per page is plenty.

## Method 3: Text Plus a Directions Link

Google's Maps URLs let you open Google Maps from any link, and the documentation says: "You don't need a Google API key to use Maps URLs." The two forms you need:

- Search: `https://www.google.com/maps/search/?api=1&query=Corner+Cafe+12+High+Street`
- Directions: `https://www.google.com/maps/dir/?api=1&destination=Corner+Cafe+12+High+Street`

Google says `api=1` is required in every request (without it, "all parameters are ignored"), values must be URL-encoded, and `travelmode` accepts driving, walking, bicycling, two-wheeler or transit. The docs make no statement about cost for Maps URLs, so check their page if you expect heavy use.

The big advantage over an iframe is measurement. A click inside an embedded frame is not reported to your analytics, but a normal link is. We use the directions link as the main thing to count.

Pair it with a tap-to-call link. MDN notes that on cellular devices a `tel:` link autodials the number, while on other devices the behaviour varies (some open a calling app or offer to save the number). Write the number as text as well, so it is readable and copyable.

Accessibility detail: if a link opens in a new tab, say so in the link text, for example "Get directions (opens in new tab)", as MDN recommends. Use descriptive text, never "click here."

## Privacy Check: Does Your Map Need Consent?

This is where UK owners especially should pause. Under the UK's PECR rules, the ICO's guidance says you must not store information on, or access information stored on, a visitor's device unless an exception applies. You must tell users what the technologies do and get prior consent, and "continuing to use a website is not valid consent." The ICO also says the rules cover technologies you incorporate from other organisations, and that you are responsible for understanding how third-party code in your service behaves.

The ICO's exceptions page discusses embedded video and social plugins, and advises configuring embedded content not to set storage and access technologies "the instant someone visits the page." It does not mention maps. So there is no ICO ruling that says a map embed does or does not need consent. What you can do:

1. Open your contact page in a private browser window, open the developer tools, and look at what is stored on the device after the map loads. If you are not sure how to read it, ask your web person or a consent-management tool.
2. If your cookie banner is set to block third-party embeds until accepted, the map will need a placeholder with your address and a link. That is another reason to keep the text address and the directions link.
3. If you serve EU or UK visitors, read our guides on [website cookie consent](/blog/website-cookie-consent-small-business) and [local business website GDPR compliance](/blog/local-business-website-gdpr-compliance).

This is general information, not legal advice. US, Canadian and Australian rules differ, so the same check applies to your own jurisdiction.

## A Note on Structured Data

You can tell search engines your location with LocalBusiness markup. Google's documentation lists `address` and `name` as the required properties, and recommends `geo` (latitude and longitude with at least five decimal places), `openingHoursSpecification`, `telephone` and `url`. It also states that Google "does not guarantee that features that consume structured data will show up in search results." Schema.org defines a `hasMap` property as "A URL to a map of the place" for the Place type, but Google's LocalBusiness page does not list it, so treat it as optional and do not expect a visible change.

## Measure It

The map earns its space only if people act. Set up three counts: clicks on the directions link, taps on the phone number, and visits to the contact page. Our call tracking guide shows how to count calls, and Google Business Profile's own performance report shows direction requests and calls from your listing. Compare the two over a month.

## Do This Today

1. Search your business on Google Maps and check the pin sits on your entrance and the name, address and phone number match your website.
2. Copy the embed code (Menu, Share or embed map, Embed a map, Copy HTML) and paste it into your contact page below your address and opening hours.
3. Add `title`, `loading="lazy"` and `width="100%"` to the iframe, then test it on a real phone.
4. Add a text address, a tap-to-call link and a "Get directions" link using the Maps URL format above, and name them clearly in your analytics.
5. Open the page in a private window, check what the map stores on the device, and if you have UK or EU visitors, make sure your cookie banner treats the embed correctly.

## FAQ

**Q: Is the Google Maps embed really free?**
A: Google's Maps Embed API documentation says all requests are available at no charge with unlimited usage. Google's help page for the Copy HTML route does not mention a price. Paid billing applies to other Maps Platform products, covered in our [Maps API guide](/blog/using-google-maps-api-for-local-businesses).

**Q: Will the map slow my page down?**
A: It adds an extra frame, and MDN notes every iframe uses extra memory and computing resources. Lazy loading and keeping to one map per page limit the cost. Test your page speed before and after on your own site.

**Q: Why can I not find the embed option on my phone?**
A: Google's embed instructions are written for a computer. Use a laptop, or build a directions link instead.

**Q: Do I need cookie consent for a map?**
A: The ICO's PECR guidance requires consent for non-exempt storage or access on a device and puts the responsibility on you to understand third-party code, but it does not mention maps specifically. Check what your embed stores and set your banner to match. Not legal advice.

**Q: What if I have more than one location?**
A: Give each location its own page with its own map, address, phone number and hours. Clearer for visitors, and far lighter than loading several maps together.

**Q: Can I track clicks on the map itself?**
A: Not inside the frame. Track clicks on separate links, which is why we recommend a directions link beside the map.
