## How Soon Should a Review Request Go Out?

Timing affects how a review request lands. A published Google Business Profile guide gives two patterns. In its first example, a review request is sent 2 hours after an appointment is completed. In its second, the request goes out the following morning after a service is completed ([DMLY](https://dmly.io/google-business-profile-automation-guide/), secondary). Both are examples, not measured results, so test which timing suits your service.

| Pattern | Published example | Suits | Check first |
| --- | --- | --- | --- |
| Two hours after completion | Appointment completed, wait 2 hours, send request | Short appointments finished during the day | Whether the wait ends during business hours |
| Following morning | Service completed, wait until next morning, send request | Jobs finished late in the day | Whether the message still feels timely |

Use the same short wording for either pattern, with a direct link to your review page and a clear way to opt out. Keep the message about the visit rather than asking for a specific star rating.

## How Do You Build a Workflow Without Breaking Things?

Start with one process that repeats every week, such as review requests. Write down the trigger, the wait time and the message text before you open the builder. Then work through these steps:

1. Connect only the apps that process needs.
2. Test with a dummy contact before any real customer receives a message.
3. Turn on error notifications so failed runs reach your inbox.
4. Check the run history once a week for duplicates or missed sends.
5. Add a second workflow only after the first has run cleanly for a few weeks.

## What Can Go Wrong?

Automations often fail quietly. An app connection can expire, or a form field can be renamed, and then messages stop without an obvious error. Check the run history weekly and keep error alerts on.

Not every phone system can send missed-call webhooks, so confirm this with your provider before building workflow 3. A booking edited twice can also trigger the review request twice, so add a check that stops repeat sends to the same customer.

Make offers a free plan, but its limits and paid prices change over time. Check Make's live pricing page before choosing a plan.

### Which Make workflow should I start with?

Start with a review request triggered by a completed booking. It has one clear trigger and a measurable outcome, which makes it easier to test.
