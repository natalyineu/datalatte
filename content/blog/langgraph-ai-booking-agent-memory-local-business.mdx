## What Does LangGraph Add to a Chatbot?

A plain chatbot call has no memory of its own: you must send the history each time. LangGraph's docs describe checkpointers that persist a thread's graph state as checkpoints, which is short-term, thread-scoped memory. You pass the thread in the config:

```python
config = dict(configurable=dict(thread_id="thread-1"))
```

If you use the same `thread_id` on the next call, LangGraph loads the saved state. A new `thread_id` starts an empty thread. The docs say `InMemorySaver` keeps checkpoints in RAM, so they are lost when the process restarts. For a booking agent you need a saver that writes to disk or a database.

## Which Checkpointer Should You Use?

| Checkpointer | Package | Use |
| --- | --- | --- |
| InMemorySaver | langgraph | Tests; lost on restart |
| SqliteSaver | langgraph-checkpoint-sqlite | Local development and lightweight deployments |
| PostgresSaver | langgraph-checkpoint-postgres | Several workers or a hosted database |

The PyPI page for `langgraph-checkpoint-sqlite` (version 3.1.2, released October 12, 2026) describes it as useful for local development, testing or lightweight deployments. It also warns to set `LANGGRAPH_STRICT_MSGPACK=true`, or pass an explicit `allowed_msgpack_modules` list, to limit what checkpoints can deserialize. The LangGraph docs show `PostgresSaver.from_conn_string(...)` followed by `setup()` to create its tables. The package name for Postgres is from the docs' import path and should be checked on PyPI.

## How Do You Build the Agent?

Install the packages:

```bash
pip install langgraph langgraph-checkpoint-sqlite langchain-anthropic
```

Then a minimal graph. The assistant collects the service, time, name and phone. When it has all four it ends its message with the word READY. A router sends that case to a staff approval step.

```python
from typing import Annotated, TypedDict

from langchain_anthropic import ChatAnthropic
from langchain_core.messages import AnyMessage, SystemMessage
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages
from langgraph.types import Command, interrupt

# Check current model names in Anthropic's docs before you deploy.
llm = ChatAnthropic(model="claude-haiku-4-5", temperature=0.2)

SYSTEM = (
    "You are the booking assistant for a hair salon (placeholder). "
    "Collect: service, preferred date and time, name, phone. "
    "Ask for one missing item at a time. Never invent prices or free slots. "
    "When all four are known, summarise them and end your message with READY."
)


class BookingState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    approved: bool


def assistant(state: BookingState):
    reply = llm.invoke([SystemMessage(content=SYSTEM), *state["messages"]])
    return dict(messages=[reply])


def route(state: BookingState):
    last = state["messages"][-1].content
    return "staff_review" if "READY" in str(last) else END


def staff_review(state: BookingState):
    # Pauses the graph and saves state until you resume with Command(resume=...)
    decision = interrupt(dict(summary=str(state["messages"][-1].content)))
    return dict(approved=bool(decision))


def save_booking(state: BookingState):
    if state.get("approved"):
        pass  # call your calendar or booking API here
    return dict()


builder = StateGraph(BookingState)
builder.add_node("assistant", assistant)
builder.add_node("staff_review", staff_review)
builder.add_node("save_booking", save_booking)
builder.add_edge(START, "assistant")
builder.add_conditional_edges("assistant", route)
builder.add_edge("staff_review", "save_booking")
builder.add_edge("save_booking", END)
```

The `interrupt()` call needs a checkpointer and a `thread_id`. According to the docs, you resume with `Command(resume=True)` using the same `thread_id`, and the node restarts from its beginning, so keep code before `interrupt()` free of side effects.

## How Do You Run It With Memory?

```python
with SqliteSaver.from_conn_string("bookings.db") as saver:
    graph = builder.compile(checkpointer=saver)
    config = dict(configurable=dict(thread_id="+15550100"))  # placeholder number

    out = graph.invoke(dict(messages=[("user", "Hi, can I book a colour on Friday?")]), config)
    print(out["messages"][-1].content)

    # Later, even after a restart, the same thread_id continues the chat:
    out = graph.invoke(dict(messages=[("user", "Make it 3pm. Name is Ana, phone 555 0100.")]), config)

    # When the graph pauses, the payload is in out["__interrupt__"].
    # Staff approve, and you resume:
    graph.invoke(Command(resume=True), config)
```

`SqliteSaver.from_conn_string` is a context manager, as the PyPI example shows, so keep the graph inside the `with` block.

## How Do You Connect It to WhatsApp?

Meta's WhatsApp Cloud API delivers messages to your endpoint as HTTP POST requests with JSON payloads. Incoming text is at `entry[].changes[].value.messages[].text.body`, the sender is `messages[].from`, and the message has an `id`. Meta retries for up to 7 days when your endpoint does not return HTTP 200, and retries can cause duplicates, so the handler should be idempotent.

```python
from fastapi import FastAPI, Request

app = FastAPI()
seen: set[str] = set()  # use a database table in production


@app.post("/whatsapp")
async def inbound(request: Request):
    body = await request.json()
    for entry in body.get("entry", []):
        for change in entry.get("changes", []):
            for msg in change.get("value", dict()).get("messages", []):
                if msg["id"] in seen or msg.get("type") != "text":
                    continue
                seen.add(msg["id"])
                # run graph.invoke(...) with thread_id = msg["from"], then send the reply
    return dict(ok=True)
```

Webhook verification and signature checks are not covered here. Follow Meta's documentation for them before going live. See our [WhatsApp Business customer service guide](/blog/how-to-use-whatsapp-business-for-customer-service) for the business side.

## FAQ

### What is a thread_id in LangGraph?

It is the key in the config that tells LangGraph which saved conversation to load. The same thread_id continues a conversation, and a new one starts empty.

### Is SqliteSaver safe for production?

PyPI describes it as suited to local development, testing or lightweight deployments. For several workers or heavier traffic, the docs show PostgresSaver.

### How do I add human approval?

Call `interrupt()` in a node and resume with `Command(resume=...)` using the same thread_id. A checkpointer is required.

### Can I use a model other than Claude?

Yes. LangGraph is model-agnostic. This example uses `langchain-anthropic`.

### Should the agent confirm bookings by itself?

For a small salon, no. Keep a staff approval step until the agent has handled enough test conversations.
