To build an MCP server for a local business in Python, write a small program that exposes your menu, opening hours and loyalty records as tools an AI agent can call, then register it with an MCP client such as Claude Desktop. A tutorial in the sources gives Python 3.9 or newer as the starting requirement for the FastMCP approach ([LinkedIn guide](https://www.linkedin.com/posts/prasanth-ss-a39b0a1a1_intellectai-intellectai-ai-activity-7406171035869491200-0MEg)). A four-tool coffee shop server takes a few hours for someone comfortable with basic Python. Every price in the examples is a placeholder.

## Why would a local business need its own MCP server?

Off-the-shelf connectors can link an AI assistant to calendars, notes and databases, but none of them knows your prices, your appointment rules or your loyalty tiers. A custom server closes that gap. It exposes only the data the owner chooses, and the agent queries it the same way it queries any other tool.

The build is worth it when the agent must answer questions about specific products or policies, when that data changes often, or when the agent needs to look up or update the business's own records. It is probably not worth it when a general connector already covers the job, or when a static FAQ page would do.

The [MCP documentation](https://modelcontextprotocol.io) describes the protocol itself, including the transport options. Read it before choosing how the server will be hosted.

## How does FastMCP keep the code short?

FastMCP lets a developer turn a normal Python function into an AI-callable tool with a decorator. The tutorial describes this as any Python function becoming an AI-usable skill, with examples such as math operations, database queries and API calls ([LinkedIn guide](https://www.linkedin.com/posts/prasanth-ss-a39b0a1a1_intellectai-intellectai-ai-activity-7406171035869491200-0MEg)). The sketch below follows that pattern. Treat it as a starting point and test it before use.

```python
import json
from fastmcp import FastMCP

mcp = FastMCP("coffeeshop-local")

@mcp.tool()
def get_menu(category: str = "all") -> str:
    """Return the current menu, or one section of it."""
    with open("menu.json") as f:
        menu = json.load(f)
    if category == "all":
        return json.dumps(menu, indent=2)
    return json.dumps(menu.get(category, {"error": "category not found"}))

if __name__ == "__main__":
    mcp.run(transport="sse")
```

The tutorial starts the server with `mcp.run(transport="sse")` and connects it to Claude Desktop or another MCP-compatible IDE. Other transports exist, so the current documentation should be checked before deployment.

## What should the coffee shop server expose?

The first version should stay small. A practical set is four tools: a menu lookup, a loyalty balance check, an opening-hours lookup and a points addition after purchase. Each tool reads from a plain file the owner controls, such as `menu.json`, `hours.json` or `customers.csv`, so updating the business is a file edit, not a code change.

Use one function per job and give each a description the agent can read. Clear descriptions help the model choose the right tool. Add holiday closures to the hours file as dated entries, so the agent answers correctly on a bank holiday.

Sample placeholder data for a coffee shop might look like this:

```json
{
  "hot_drinks": [
    { "name": "Oat Milk Latte", "price": 6.50 }
  ],
  "last_updated": "2026-06-13"
}
```

The $6.50 price is an assumption for illustration. The owner should replace it with actual figures.

## How do you test and connect the server?

Each tool should be tested directly before the server is connected to an AI client. Call every function with a valid input, an invalid input and an edge case, such as a phone number that is not in the loyalty file or a holiday date. A server that crashes on bad input can fail silently from the client's side, so errors should be caught inside the tool and returned as a clear message.

To connect the server to Claude Desktop, add an entry under `mcpServers` in the Claude Desktop configuration file. Use the absolute path to `server.py`, restart the app, then ask a question with a known answer, such as the price of one menu item. If the answer matches the file, the wiring works.

## Which security rules apply to write tools?

Any tool that changes data needs stricter rules than a read-only tool. Inputs should be validated on the server, not in the prompt. A points tool should reject negative values and cap a single transaction at a sensible maximum, so a bad request cannot drain or inflate balances.

Credentials should stay out of the server entirely. No tool should return payment keys, Wi-Fi passwords or staff logins. Write tools should be limited to the minimum needed, and every write should be logged with a timestamp, its inputs and its result, creating an audit trail.

If the server is deployed over HTTP rather than run locally, it needs authentication such as a long random token. A server that anyone can reach can be called by anyone.

## What is the launch checklist?

1. Confirm Python 3.9 or newer and install the FastMCP or MCP SDK package.
2. Store menu, hours and loyalty data in plain files, and date each one.
3. Test every tool with valid, invalid and edge-case inputs.
4. Connect the server to one client and check three answers against the source records.
5. Add logging and rate limits to every write tool before going live.
6. Review the data files monthly and retire any tool nobody uses.

## FAQ

### Do I need to be a developer to build an MCP server?

Basic Python skills are needed, such as running commands in a terminal and editing a function. Anyone who has never written Python should allow extra time to learn it first. Many small businesses hire a developer for the build and keep the data files in-house.

### Can the server connect to live services?

Yes. A tool can call an external API, for example to read today's specials from the business website. Those calls should be fast, because a slow tool can time out in the AI client.

### Does one server work with several AI clients?

Possibly, but it depends on the transport. Local stdio servers are usually launched by a single client. Network transports can serve more than one client, so the current MCP documentation should be checked before planning for that.

### Is a custom MCP server secure by default?

No. A local stdio server is not reachable over a network, but any server exposed over HTTP needs authentication, input validation and limits on write tools.
